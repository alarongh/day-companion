# Проверки

Проверка исходников для публикации: 11 октября 2026 года.

## Автоматические проверки

- `pytest -q`: 59 тестов. Расчёты дня и сна, переход через полночь, погода по маршруту, правила одежды, импорт расписания, приватность профилей, настройка через ИИ и защита от устаревших изменений.
- Обработчики Telegram и облачный webhook проверяются с подставным API. Проверяется сохранение очередей, обработка повторных обновлений и доставка после перезапуска.
- `ruff check companion tests scripts cloudflare/src`.
- `python -m companion.demo`: автономная демонстрация с искусственной погодой и расписанием.
- Gitleaks проверяет файлы и историю Git перед публикацией; в CI выполняется повторная проверка истории.

## Исправления взаимодействия

- Проверен сценарий нового пользователя: добавление района без ИИ и расписания, получение погоды, восстановление после неверного диапазона температуры.
- Проверяются реальные байты multipart-запроса, имя файла, отсутствие дублирующего поля документа и отсутствие `text: null` в подтверждении кнопки.
- Облачная отправка файла проверена запросом с искусственными данными и заведомо недействительным получателем (`chat_id=0`): Telegram корректно разобрал запрос и вернул JSON `chat not found`. Это проверка транспорта без отправки человеку.
- Время фактического получения файла на устройстве пользователя автоматическими тестами не проверяется.

## Свежесть сводок и отдельный режим сна

- Два последовательных запроса погоды выполняют два обращения к API и используют новые значения ответа.
- Перед напоминанием проверяется источник даже после недавнего обновления; перенос на более раннее время выявляет фоновая проверка. Доставленные напоминания не вызывают дополнительных проверок каждые 20 секунд.
- Перенос пары и смена аудитории пересчитывают сообщение; недоступность источника отмечается явно. Отложенная сводка, перенесённая позже, может быть поставлена в очередь заново с тем же дневным ключом.
- Облачные проверки подтверждают новый прогноз при каждой попытке доставки, удаление устаревшей очереди и отсутствие блокировки ответа пользователю, пока планировщик ждёт доступ к профилю.
- Отдельный пользователь включает режим сна без города, загружает статичное расписание и получает расчёт. Подключённая группа и другие профили сохраняются. Проверены собственный цикл недель и переход через полночь.

## Проверки развёртывания

Во время разработки проверялись работа облачного webhook, состояние очереди, перенос SQLite с сопоставлением контрольных сумм и обработка команд. Адреса рабочего сервера, идентификаторы аккаунтов, содержимое базы и секреты в этот репозиторий не включены.

После собственного развёртывания нужно проверить `/start`, `/config`, загрузку расписания и получение уведомления в своём Telegram. Тесты с подставным API не подтверждают скорость доставки на устройство.

## Что не подтверждено

- Сборка и запуск Docker-образа в Docker Engine.
- Универсальное распознавание произвольных PDF и фотографий расписания: поддерживается ограниченный формат строк и колонок, качество зависит от OCR.
- Длительная непрерывная работа и поведение при исчерпании облачных квот.
- Абсолютно однократная доставка при аварийном завершении после отправки сообщения, но до записи результата в SQLite.
